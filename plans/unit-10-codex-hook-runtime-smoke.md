# Unit-10: Codex Hook Runtime Smoke

## Goal

Verify the Codex hook files generated by `install --codex` against the local
Codex runtime, and record the boundary between generated-file correctness and
actual hook execution.

## Scope

- Install Codex workflow files into a disposable vault.
- Smoke-test the generated hook script and `.codex/hooks.json` shape.
- Run `codex exec` against the disposable vault with hooks enabled.
- Fix Codex-side hook generation issues found during the smoke test.
- Document any runtime gap without changing Claude behavior, MCP, or backend
  vault/search/fetch code.

## Out of Scope

- MCP.
- Backend fetch/search/sync/lint changes.
- Claude Code hook or skill changes.
- Treating hooks as a hard enforcement boundary.

## Specification Check

OpenAI Codex hook docs rechecked on 2026-05-08:
https://developers.openai.com/codex/hooks

Design implication:

- Keep the repository hook config in `.codex/hooks.json`.
- Keep `[features].codex_hooks = true` in `.codex/config.toml`.
- Use the documented hook handler `timeout` field.
- Continue treating hook output as contextual guidance, not a security layer.

## Runtime Smoke

Disposable vault:

```text
/private/tmp/hpr-codex-hook-runtime.RxOQLm
```

Local Codex runtime:

```text
codex-cli 0.128.0
codex_hooks stable true
```

Checks performed:

- `hyperresearch install --codex ... --json` generated `AGENTS.md`,
  `.agents/skills`, `.codex/agents`, `.codex/config.toml`,
  `.codex/hooks.json`, and `.codex/hooks/hyperresearch_pre_tool_use.py`.
- The hook script emits SessionStart additional context when invoked directly
  with a vault `cwd`.
- The hook script emits a PreToolUse system message for direct
  web-fetch-looking Bash commands when invoked directly.
- `codex exec --json --enable codex_hooks` loaded the generated `AGENTS.md`
  and project skills.
- The same `codex exec` runs did not emit hook lifecycle events or inject the
  expected hook context, even with a git-initialized disposable vault and
  attempted project trust overrides.

## Fixes

- Generated hook commands now call the hook script by absolute path instead of
  relying on `$(git rev-parse --show-toplevel)`.

This matters because a Hyperresearch vault does not have to be a git
repository. If Codex fires the hook in a non-git vault, the previous command
could fail before reaching the hook script.

## Finding

The generated hook files are structurally correct and the script behavior is
tested, but actual hook execution was not observed through `codex exec` in the
local `codex-cli 0.128.0` runtime. Treat the Codex hook layer as generated but
runtime-unverified until an interactive trusted Codex session or a clarified
Codex exec trust path confirms it.

Generated `AGENTS.md`, skills, custom agents, and the `hyperresearch ... --json`
backend path remain the primary verified Codex parity surfaces.

## Verification

- `hyperresearch install --codex /private/tmp/hpr-codex-hook-runtime.RxOQLm --json`
  regenerated the hook config with an absolute script path and `timeout`.
- `codex exec --json --enable codex_hooks ...` still showed no hook lifecycle
